# 提示词工作流

当用户只有一个卡通 IP、还没有动态素材时，使用这个流程。

完整链路：

```text
卡通 IP 参考图 -> 静态生图提示词 -> 静态图生成 -> 图生视频提示词 -> MOV 视频生成 -> MOV 转 WebM
```

## 信息收集

先询问：

1. 卡通 IP 角色参考图。
2. 需要哪些状态/动作。
3. 每个状态是循环状态还是一次性状态。
4. 每个状态是否需要道具或符号。
5. 输出偏好：直接透明素材、先导出透明 MOV，还是先导出绿幕 MOV。默认推荐先导出 MOV，再用本 Skill 转 WebM。

如果用户不知道怎么选，使用 5 个标准状态：

```text
任务进行中、任务完成、任务失败、任务暂停/休息、喝水提醒
```

## 静态图片文件名规则

生图阶段使用当前桌宠工程的静态图命名格式：

| 状态 | 静态图片文件名 |
|---|---|
| 任务进行中 | `任务进行中.png` |
| 任务完成 | `任务完成.png` |
| 任务失败 | `任务失败.png` |
| 任务暂停/休息 | `任务暂停.png` |
| 喝水提醒 | `喝水提醒.png` |

不要把视频/WebM 文件名用于静态图。`任务进行中_无缝循环.webm` 和 `任务暂停_休息_无缝循环.webm` 是后续动态素材文件名；静态图片不要命名为 `任务进行中_无缝循环.png` 或 `任务暂停_休息_无缝循环.png`。

## 输出顺序

不要一上来直接写视频提示词。推荐按下面顺序交付：

1. 动作清单：确认每个状态的用途、动作、道具、是否循环。
2. 静态生图提示词：每个状态一条，供用户先生成纯绿幕静态素材图。生图阶段只写图片提示词，不掺入视频生成说明。
3. 静态图检查要点：角色是否一致、比例是否稳定、是否完整入镜。
4. 图生视频提示词：基于已通过的静态首帧图生成视频。
5. MOV 命名要求：告诉用户或第三方工具导出 MOV 后按标准槽位命名。
6. MOV 转 WebM 指令：用户发回 MOV 路径后，直接执行转换。

## 角色身份锁定块

根据用户的参考图创建角色身份锁定块。这个描述只应该描述用户自己的 IP：

```text
参考图中的同一个角色，保持参考图的身份、头身比、发型、服装、主要配色、面部比例和整体风格。不要改变角色年龄、体型、发色、服装主色或画风。若动作需要更多空间，只允许整体等比缩小，不允许拉伸身体或改变比例。
```

不要写死任何示例角色细节，除非这些细节确实出现在用户自己的参考图里。

## 对/错手持举牌规则

只要状态含义是“完成、正确、通过、成功、done、correct、approved”，静态图必须画成角色手持白色圆形牌，白色圆柱手柄，牌面上是绿色正确勾号。

只要状态含义是“失败、错误、不通过、驳回、failed、wrong、rejected”，静态图必须画成角色手持白色圆形牌，白色圆柱手柄，牌面上是红色叉号。

这两个状态都必须让角色的手明确握住牌柄，牌子与手有接触，手柄可见。禁止把勾号或叉号画成头顶漂浮 icon、悬空符号、背景符号、额头符号、角落贴纸或单独的大叉/大勾。禁止只画双手抱歉手势却没有手持牌。

## 静态生图提示词模板

```text
使用参考图作为角色一致性基准。{character_identity_block}
动作状态：{state_label}。
画面类型：桌宠角色静态素材图，只包含角色和完成动作所必需的简化道具组合，不是场景插画、不是办公照片、不是电影截图、不是房间画面。允许像合格参考一样出现“纯绿幕前的 Q 版角色 + 小桌 + 小椅子 + 笔记本电脑”组合，但它必须是独立桌宠道具立绘，不是办公室场景。
动作画面：{scene}。
情绪：{emotion}。
道具：{props}。
背景：纯色 chroma key green 绿幕，建议 #00FF00 或接近纯绿；背景平整均匀，无纹理、无阴影、无渐变、无光斑、无景深、无地面线、无房间透视。
构图：1:1 正方形，单个角色居中，正面或轻微正面视角，平视镜头，近似正交视角。角色、头发、手、脚、裙摆、鞋子、耳环、牌子、杯子、电脑、键盘、桌子、椅子等全部元素都必须完整在画面内部，任何元素都不能碰到画面边缘，不能被裁切，不能出画。整体组合可以像参考图一样占画面主体，但必须保留清楚的纯绿安全边距：顶部和底部至少 6%-10%，左右至少 10%-16%。角色加道具的整体高度建议占画布高度 78%-88%，不能超过 90%；整体宽度建议占画布宽度 60%-78%，不能超过 82%。
角色比例：保持参考图同一个角色，头身比、脸型、五官、发型、服装、配色和画风不变。禁止把角色画高、画瘦、拉长腿、缩小头、改变年龄、改变体型或改变服装主色。动作需要更多空间时，只允许整体等比缩小，不能改变身体比例。
道具：道具必须简化、可爱、完整入画，并围绕角色布置。任务进行中可以有简化小桌、小椅子、笔记本电脑或小键盘，效果应像参考图：角色坐在绿幕前的小桌旁，笔记本放在桌上，桌腿和椅子完整可见。不能出现大型办公桌、台式大显示器、真实电脑桌、房间环境，也不能让电脑遮住角色脸部、头发或主体轮廓。完成、失败、喝水等状态不要用写着文字的卡片表达动作。
完成/失败手持牌：任务完成和任务失败不能只用表情、手势或悬空图标表达。任务完成必须是角色手持白色圆形牌，白色圆柱手柄，牌面绿色勾号；任务失败必须是角色手持白色圆形牌，白色圆柱手柄，牌面红色叉号。角色至少一只手要握住牌柄，手柄从手中延伸到圆形牌面，牌面和手柄都完整入画，不能遮住角色脸。勾号或叉号必须在白色圆牌内部，不能漂浮在角色头顶或画面角落。
风格：保持参考图原本画风，高清桌宠素材，角色和道具边缘干净，不能有绿色反光、绿色污染或半透明绿边。
禁止：白色贴纸描边、粗白边、光晕边、阴影背景、复杂场景、真实桌面透视、深色房间、蓝色屏幕光污染、大屏幕挡脸、大桌子挡身体、桌腿出框、椅子出框、近景特写、半身图、只画头肩、侧脸大角度、角色半身裁切、头发出框、脚出框、手出框、道具出框、悬空勾号、悬空叉号、头顶漂浮符号、角落红叉、额头红叉、只有抱歉手势没有手持牌、角色比例变高、腿被拉长、身体非等比变形、无关文字、水印、logo。
```

## 视频提示词模板

```text
【全局硬性约束】全程固定镜头，固定机位原地拍摄，禁止推拉摇移、变焦、画面尺度变化或镜头晃动。角色从第一帧到最后一帧全身完整可见，头发到脚不裁切。角色始终位于画面中央和原地，只允许角色自身和道具做小幅原地动作，不允许位移、滑动、漂移或跑出画面。保持参考图角色比例和画风，不要变高、不要拉长腿、不要改变头身比；如需要适配画面，只允许整体等比缩小。
```

## 无缝循环规则

用于 `working`、`paused` 或任何会长时间停留在屏幕上的状态：

```text
【无缝循环硬性约束】第一帧和最后一帧必须回到同一个姿态、表情、角色位置、道具位置、构图和镜头尺度。动作只能是小幅往返运动，例如呼吸、眨眼、发丝轻摆、手部轻微动作。不能突然加速、转身、缩放、漂移或停在半途。
```

## 一次性动作规则

用于 `done`、`failed` 和短提醒状态：

```text
【一次性动作约束】这条视频不需要无限循环，但开始和结束必须稳定，角色不能漂移，动作结束时停在清晰可读的状态，方便桌宠播放后自动切回待命或休息状态。
```

## 休息闭眼规则

如果状态是睡觉、休息、小憩、躺平、午休或暂停，默认要求角色闭眼，除非用户明确要求睁眼。

## 用户给 MOV 路径后的规则

当用户发来 MOV 路径时，不要停留在说明层面。应当：

1. 确认 MOV 文件是否存在。
2. 判断它对应哪个标准槽位。
3. 选择输出路径 `08_可替换素材/{标准文件名}.webm`。
4. 调用 `scripts/convert_mov_to_webm.py` 转换。
5. 转换后调用 `scripts/validate_replaceable_assets.py` 校验。

如果用户一次发来多个 MOV 路径，逐个转换。文件名无法判断槽位时，再问用户对应关系。
