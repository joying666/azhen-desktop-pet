# Agent 桌宠

使用这个 Skill 帮用户从一个卡通 IP 参考图制作桌宠素材包。默认协作链路是：

```text
卡通 IP 参考图 -> 纯绿幕静态生图提示词 -> 图生视频提示词 -> 用户/第三方生成 MOV -> MOV 转 WebM -> 替换 5 个标准素材
```

如果用户已经有动态素材，也可以跳过前面的提示词阶段，直接替换或转换素材。

## 标准素材槽位

桌宠默认使用下面 5 个素材槽位：

| 槽位 | 含义 | 标准文件名 |
|---|---|---|
| `working` | Agent 正在运行、思考、打字或调用工具 | `任务进行中_无缝循环` |
| `done` | Agent 成功完成任务 | `任务完成` |
| `failed` | Agent 执行失败或报错 | `任务失败` |
| `paused` | Agent 空闲、等待、暂停、阻塞或休息 | `任务暂停_休息_无缝循环` |
| `water` | 工作时间喝水提醒 | `喝水提醒` |

支持扩展名：`.webm`、`.gif`、`.webp`、`.apng`、`.png`、`.mp4`。最推荐透明背景 `.webm`，同名素材优先级为 `.webm -> .gif -> .webp -> .apng -> .png -> .mp4`。

静态生图阶段使用当前桌宠工程的图片文件名：

| 状态 | 静态图片文件名 |
|---|---|
| 任务进行中 | `任务进行中.png` |
| 任务完成 | `任务完成.png` |
| 任务失败 | `任务失败.png` |
| 任务暂停/休息 | `任务暂停.png` |
| 喝水提醒 | `喝水提醒.png` |

注意：带 `_无缝循环` 的文件名只用于后续视频/WebM 动态素材，不用于静态图片。

## 工作流程

1. 判断用户当前处在哪个阶段：只有卡通 IP、已有静态图、已有视频提示词、已有 MOV，还是已有 WebM/GIF/WebP/APNG/PNG。
2. 如果用户只有卡通 IP 参考图，先进入完整制作链路：
   - 询问用户需要几个状态/动作；如果用户没有想法，默认使用 5 个标准状态。
   - 为每个状态生成一条静态生图提示词。生图阶段只写静态图片提示词，不掺入视频生成说明。
   - 等用户确认静态图方向后，再为每个状态生成图生视频提示词。
   - 提醒用户把生成好的 MOV 路径发回来。
   - 收到 MOV 路径后，转成对应的标准 WebM 文件。
3. 根据用户现有素材选择分支：
   - **直接替换分支：** 用户已经有 WebM / GIF / WebP / APNG / PNG 素材。把文件重命名或复制成 5 个标准槽位文件名。
   - **MOV 转换分支：** 用户有 MOV 导出文件。用 `scripts/convert_mov_to_webm.py` 转成透明 WebM，再放进 `08_可替换素材/`。
   - **提示词生成分支：** 用户还没有素材。先询问角色参考图和需要的状态，再写图片提示词和视频提示词。读取 `references/prompt-workflow.md`。
   - **不会使用 Skill 分支：** 用户想把流程拆成普通提示词、教程、手册或给别人复制粘贴使用。读取 `references/step-by-step-prompts.md`，按步骤输出。
4. 用 `scripts/validate_replaceable_assets.py` 校验素材文件夹。
5. 如果桌宠 App 正在运行，重启或重新加载 App，让新素材生效。

## 替换规则

- 普通自定义不需要改 App 代码，优先只替换 5 个文件。
- 对用户可见的文件名保持中文，方便非技术用户理解槽位。
- 每个槽位使用一个明确文件。除非用户要自定义状态，否则不要让用户编辑 JSON。
- 长时间显示的状态应做成无缝循环：`working` 和 `paused`。
- 一次性状态应短暂播放后回到待命/休息：`done`、`failed`，以及通常的 `water`。
- 开源输出里不要包含用户私有角色素材、API Key、本机绝对路径或模型账号配置。

## MOV 转换分支

当用户有 `.mov` 文件时，读取 `references/mov-to-webm.md`。

如果用户给出一个或多个 MOV 路径，直接进入转换，不要再要求用户重新生成素材。先确认每个 MOV 对应哪个槽位：`working`、`done`、`failed`、`paused`、`water`。如果文件名已经包含 `任务完成`、`任务失败` 等标准词，可以自动推断槽位。

常用命令：

```bash
python3 scripts/convert_mov_to_webm.py --input "任务完成.mov" --output "08_可替换素材/任务完成.webm"
python3 scripts/convert_mov_to_webm.py --input "任务完成_绿幕.mov" --output "08_可替换素材/任务完成.webm" --green-screen
python3 scripts/convert_mov_paths_to_standard_webm.py "任务完成.mov" "任务失败.mov" --output-folder "08_可替换素材"
```

如果用户有 5 个 MOV 文件，把每个 MOV 转成对应的标准文件名。

## 提示词生成分支

只有收集到下面信息后，才开始写生成提示词：

- 卡通 IP 角色参考图路径。
- 需要的状态/动作。
- 每个状态是循环状态还是一次性状态。
- 每个状态是否需要道具或可读符号。
- 输出方式是先做绿幕 MOV、先做透明 MOV，还是直接做透明 WebM。默认推荐“先做 MOV，再转 WebM”，因为很多视频工具和设计工具更容易导出 MOV。

写提示词时，角色身份锁定块必须从用户自己的参考图提炼。不要写死示例角色的发型、服装、名字或配色。

提示词模板和硬性约束见 `references/prompt-workflow.md`。

输出提示词时，建议按这个结构交付：

```text
1. 动作清单
2. 静态首帧图提示词
3. 图生视频提示词
4. MOV 文件命名要求
5. 用户生成 MOV 后如何发路径给你
```

## 分步提示词手册

如果用户担心别人不会安装或使用 Skill，要把流程拆成一段段可以复制粘贴的提示词，读取 `references/step-by-step-prompts.md`。

优先输出下面这些步骤：

```text
1. 多个不同状态的静态生图元提示词
2. 静态图质检提示词
3. 图生视频提示词
4. MOV 命名和交付提示词
5. MOV 转 WebM 提示词
6. 替换桌宠素材提示词
```
